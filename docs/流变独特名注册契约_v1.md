# 流变·独特名注册契约 v1

> contract-version: 1.0（2026-10-01，基石执笔；取代《流变独特名注册契约_骨架_v0.1》中已钉的待决项）
> 参考实现：`dsh-liubian-infra`（infra-plugin/，本契约随实现同批交付）
> 管理员定义（2026-10-01）：独特名 = 每个智能体**全局独热唯一**的名字编码；注册时自动从名字派生**哈希**作为身份唯一标识符；全家族插件**统一调用注册表**。

## 1. 语义（管理员已钉，v1 定案）

| 项 | 定案 | 依据 |
|---|---|---|
| 作用域 | **全局唯一**（白泽门禁①的「全局」半边；「房间内唯一」仍归被炉本地 members 机制，不入本注册表） | 管理员 2026-10-01「全局独热唯一」 |
| 唯一性算法 | **注册时拒绝**（名字一经注册永久保留；`retire` 只停用不回收） | 管理员「独热」；骨架 §2-3 |
| 身份标识 | 名字派生 **SHA-256 哈希**（见 §2）；短 ID 兼容被炉「前 8 位」惯例（门禁②） | 管理员「哈希作为身份唯一标识符」 |
| 与 30 花名体系 | 正交平行（白泽 06:12 定性：会话派生运行身份 vs 跨会话持久身份，在昵称处相交）；本注册表记录的是智能体/参与者的**持久名** | 骨架 §3 + 群共识 |

## 2. 派生规则（消费方自算 hash 必须逐字对齐——标准 §8 同源派生函数纪律）

```
name    = String(raw).trim().normalize('NFC')
          （非空；≤64 字符；不含控制字符；不以 '@' 或 '#' 开头）
name_key = name.toLowerCase()               ← 大小写不敏感唯一
hash     = SHA256(UTF-8(name)) 小写 hex      ← 64 位，全局唯一标识符
short_id = hash 的最短唯一前缀，长度 ≥8       ← git 式；无碰撞时恰为 8
```

- 短 ID 随表演化：新注册若造成 8 位前缀碰撞，**相关条目一并自动扩位**（最小 9 位，依此类推）。
- 消费方**不要自己缓存 long-lived 的 short_id 推导逻辑**——要 hash 用 §3 只读接口查，short_id 仅作展示/路由。

## 3. 注册表与统一查询接口

- **文件**：`C:\Users\Feng\.dsh\liubian-infra\registry.db`（SQLite **WAL**，busy_timeout 5s）
- **单写多读**：只有 `dsh-liubian-infra` 插件写；其他插件一律**只读**。
- **智能体侧（LLM 调用）**：工具 `_dsh_external_dsh_liubian_infra`
  `register / verify / lookup(name|id) / list / retire / status`
- **插件代码侧（程序调用）**：直接只读打开 DB——
  - Python：`sqlite3.connect('file:C:/Users/Feng/.dsh/liubian-infra/registry.db?mode=ro', uri=True)`
  - Node：`import { DatabaseSync } from 'node:sqlite'` 只读查询
- 表结构：

```sql
identities(
  name TEXT PRIMARY KEY,          -- NFC 后的注册名
  name_key TEXT NOT NULL UNIQUE,  -- 小写化唯一键
  hash TEXT NOT NULL UNIQUE,      -- SHA-256 全哈希（权威标识）
  short_id TEXT NOT NULL,         -- 当前最短唯一前缀（随表演化）
  status TEXT NOT NULL DEFAULT 'active',  -- active | retired
  note TEXT, created_at TEXT NOT NULL, retired_at TEXT, retired_note TEXT
)
```

- **降级链（白泽门禁③，消费方接入时必须声明进 §5 表）**：注册中心不可用（DB 缺失/锁死/基建插件离线）时，消费方退回各自本地命名/缓存继续业务，不阻塞。
- 写入约束：任何消费方**不得直接写注册表 DB**——需要注册/停用走工具或找基石。
