## §0 范围与排除

**适用**（三类家族内接口）：
1. **插件间服务**：`ctx.provide` / `ctx.reflect.get` 通道（liubianInfra / liubianWiki / kotatsuBoard）；
2. **文件级接口**：被跨插件读写的数据文件与共享配置（config.json 共享键、lessons*.json、pending_promotions.jsonl 等）；
3. **算力端点**：无状态外部服务进程的 HTTP 直连（8082，见 §13）。

**不适用**：
- 本机管理面板 HTTP 面（`/api/<包名>?op=…`）——那是 **UI 面**，不是插件间接口（拾遗申报）；其形态规范见 §12；
- 宿主核心服务（tools / llm / agents / webServer / agentDefaultModel 等）——那是宿主 API，不属于家族协议管辖。

## §1 服务命名与版本

1. 服务名 = `liubian<能力名>`（现有：liubianInfra / liubianWiki；被炉系例外 kotatsuBoard，已成型不追改）。
2. 服务对象**必须带 `version` 数字字段**，消费方首次取用时校验（`svc.version >= 期望主版本`）。
3. **能力协商（预留，不实现）**：`version` 数字表达不了"有哪些方法"（拾遗为兼容旧基建被迫做三级降级）。v2 预留 `svc.capabilities()` 或契约内 version→方法表。

## §2 挂载与发现

4. **提供方**：`ctx.provide(名, svc)` 优先，`ctx.reflect.provide` 回退；两者皆无 → 记 warn、服务缺席（不抛）。
5. **消费方**：`ctx.reflect.get(名) ?? ctx.get(名)`；**拿不到或版本不符 → 明确报错，禁止静默降级**（玉簪死记录案的教训：静默改本地名 = 两处真相）。
6. **降级本身是正当的，但必须显式且登记**，两类严格分开：
   - 注册中心/服务**不可达** → 允许按**已登记**的降级链走，且**必须打一行日志、声明损失了什么**（守夜人口径："不静默"的完整含义 = 让调用方知道损失了什么）；
   - 对象**已注销 / 已删除（墓碑）** → **禁止回落本地副本**（离线与已删长得一样就是事故，墓碑优先于降级）。
7. **挂载日志双行（强制）**：提供方装载成功必须打「版本戳行」（`vX.Y.Z 已挂载：…`）+「服务戳行」（`跨插件服务已挂载：<名> v<N>（via）`）。这是消费方与管理员唯一的自检锚点。

## §3 调用形态

8. **绝不抛**：一切失败折成 `{ ok:false, error }`，消费方免 try/catch。
9. **幂等优先**：重复调用安全（`removed:0` / `unbound:0` / `alreadyForgotten` 形态）。
10. **部分失败零写入**：多步写入包事务（BEGIN→…→COMMIT，异常 ROLLBACK）。
11. **幂等键（预留）**：跨系统重试场景显式收 `idempotencyKey`；现状各服务的内建幂等属特例，不强制回改。

## §4 归因与身份

12. 服务通道**没有"调用方会话"概念**：需要归因的调用，消费方**必须显式传来源会话哈希**（`sessionHash` = `sha256(sessionId)[:8]`）；提供方**只收会话哈希、不收自由格式执行者名**——身份解析永远走注册中心（executor 不可覆盖，冒名在结构上不可能）。
13. 提供方对程序化调用统一打来源标记（`fromRef: 'svc:'` 前缀），账目可区分"人发的"与"程序发的"。
14. **推论（强制）**：消费方自备业务坐标字段（如便签的 `<池键>/<id>`），**永远不要依赖来源标记传递业务信息**——来源标记会被提供方改写（青简 v0.7.1 实证）。

## §5 门禁与名单

15. 操作对象必须在显式名单内（`roster()` 先例：有独特名 + 已绑定会话 + 有工作区归属）；名单外**拒绝且不落库**；注册中心不可达时 `roster()` 返回空、发送明确报错，不静默。

## §6 单写者与只读直连申报

16. 消费方**绝不直写**提供方的库；写动作只能走提供方的服务面或工具面。
17. **只读直连允许，但必须申报**（拾遗提案，采纳）：`mode=ro` 打开 + 进 §14 申报表（谁｜读什么｜降级行为｜通报对象）。申报是防止"读侧悄悄长出耦合"的唯一手段。

## §7 数据文件即接口

凡被跨插件读取的数据文件（池文件、账目 jsonl、共享配置）：
18. **JSON 单文档必须带顶层 `version` 字段**；**字段只增不改**；读侧必须容忍未知字段。
19. **JSONL 版本约定（本版裁定，待终审）**：**首行 `_meta` 行**——`{"_meta":true,"schema":"<名>","version":N}`。新文件强制；存量文件由写方在宿主内一次性补插；**读侧必须容忍"首行不是 _meta"的旧形态**。理由：append-only 日志常被尾读，逐行塞版本既膨胀、尾读又拿不到全貌；首行是文件级自描述的标准位。
20. **池键 = 会话哈希前 8 位**，写死进协议；跨文件归因统一由基建提供"池键→身份"反解入口（`infra binding session=<池键>`），消费方不得各自实现第二套派生。
21. 数据文件的**公共字段清单**须在其属主的契约或 §14 申报行里声明（pending_promotions.jsonl 目前无契约，待青简补一行）。

## §8 跨系统同步

22. **拉取游标是家族裁定形态，不做推送**（基建/青芷独立论证一致：无 cordis 事件耦合、无生命周期问题）。接口形状：`changes({ since })` → `{ seq, …全量快照, 事件[id > since] }`；消费方处理后推进水位。
23. **事件表只增不改**（复活/撤销也是新事件）——否则按水位轮询永远看不到状态反转（墓碑 lift 的教训）。
24. **分页（预留）**：`changes({since, limit, untilSeq})`——多消费方高频轮询后事件表会长大（基建守夜人预言）。

## §9 契约文档要求

每个服务 / 每个文件接口 / 每个算力端点，一份契约文档，必须含：
25. `contract-version` 字段（文件头）；**方法签名表**（入参/返回/错误形态）；**降级链声明表，含「降级时损失什么」一列**（守夜人提案，采纳）；**消费方登记表**；**变更通报对象**；**运维参数 + 最后核验日期**（基建守夜人提案：向量契约曾留过期阈值 4096MB（真值 12288MB），照抄即复现事故——契约不只描述接口，也承载运维参数，**过期值 = 事故配方**）。
26. 新服务**必须在家族标准 §10 登记表加一行**（服务名/归属/消费方/通报对象）——"零负担迁移"的第一步是"查得到"（基建守夜人提案）。
27. **迁移窗口（全六家承诺）**：major（改既有方法签名/语义、数据结构不兼容）= 新旧并存，窗口 = **两周或一个迭代周期取大者**，旧端点不下线不 410；minor（加方法、加字段、勘误）直接换。**窗口从首个消费方上线起算**（守夜人口径）。窗口期内**过渡别名必须有写死的退役条件 + 退役前引用面普查**（infra 的 embed 别名是活例）。

## §10 生效语义（重启才生效是默认）

28. **可装载变更（JS/impl）= 重启装载才生效**，判据 = 挂载日志版本戳；**"文件已改" ≠ "已生效"**。
29. **热更的唯一触发 = patch 内容变更**；**mtime-only touch 不触发重装配**（孪生预登记探针实测判读 A✗，青芷 2026-10-04）。`main.mjs` 的 `name`/`inject` 与 `package.json` 的 `dsh.client.inject`/`exports` **改动必须重启**。
30. **生效面分层**：接口形状以**提供方 JS 装载**为准；**数据语义常在 Python helper（每次新进程，改即生效）**——消费方把两次等待混成一次就会误报缺陷。
31. **报缺陷前先核提供方运行态版本**（判据 = 挂载日志 `vX 已挂载`）；运行态落后磁盘时产出的件天然缺新字段，不是代码缺路径（青简实证）。
32. **入口两份清单都是契约**：`main.mjs` 的宿主服务 inject 与 `package.json` 的 `dsh.client.inject` + `exports`，漏任何一项都是"热挂载看着正常、冷启动才炸"（青芷：webServer/runtime/./package.json 三连击同源）。
33. **可装载变更必涨 `PLUGIN_VERSION`**（impl 与 package.json 双处同步）——不涨就没有干净判据，全家 10-01/10-02 三次吃亏。
34. **工具 schema 是接口的一部分**：改实现必须同步 schema（wiki `move` 的 newFamilyPath、便签 nowTurn 忘声明，同族病）。

## §11 探活与可观测

35. **探活必须验功能，不验端口**：判据 = 真发一次业务请求且结果合格（向量服务 = 真嵌入且维度>0），配防抖（连续 N 轮失败才动作）。"HTTP 活着"和"活儿能干"是两回事——`/health` 200 而真嵌入超时的形态，端口探针与看门狗会一起失明（青简报障、基建修复 `abc51df`）。

## §12 面板路由形态（UI 面，供参照不强制）

36. `/api/<包名>?op=…`｜`kind:'exact'` + handler｜`sendJson`/`readBody` 帮手｜**挂载函数作用域内必须显式声明 `log`**（可选链挡不住未声明标识符——`log is not defined` 假失败：动作已生效、响应 500，被炉 4 个 op 同款踩过）。失败必须可见：客户端 `.then()` 不读响应 = 按了没反应。

## §13 算力端点例外

37. **无状态外部服务进程允许 HTTP 直连**，条件 = **有契约 + 降级链已登记**。理由：llama-server 独立进程给不出 ctx 服务面，"HTTP + 契约"就是它的接口形态。现值：8082（消费方：记忆=语义路缺席回退纯 tag；便签=只存不注）。
38. **嵌入幂等语义（预留）**：同文本同向量 + 批量上限写进契约，消费方不必自记（博物君预留）。

## §17 附：最小接入模板

### 提供方（impl.mjs，apply 内）

```js
const svc = {
  version: 1,
  myAction: async ({ sessionHash, /* 业务坐标字段 */ }) => {
    try { /* 单写者：只写自己的库；多步写入包事务 */ return { ok: true } }
    catch (e) { return { ok: false, error: String(e?.message || e) } }   // 绝不抛
  },
}
try { ctx.provide('liubianMySvc', svc) }
catch { try { ctx.reflect.provide('liubianMySvc', svc) } catch { /* warn + 服务缺席 */ } }
log?.info?.(`[${PLUGIN_NAME}] 跨插件服务已挂载：liubianMySvc v1`)          // 服务戳行（强制）
```

### 消费方

```js
const svc = ctx.reflect.get('liubianMySvc') ?? ctx.get('liubianMySvc')
if (!svc || !(svc.version >= 1))
  return '[错误] liubianMySvc 不可用——' + 已登记降级链的显式动作            // 禁止静默降级
const out = await svc.myAction({ sessionHash: mySessionHash, bizRef: '我自己的业务坐标' })
if (!out.ok) /* 按 out.error 处理，不 try/catch */
```

### 契约骨架（每个服务/文件接口/算力端点一份）

`contract-version`｜提供方与挂载判据（双行日志）｜方法签名表｜降级链声明表（**含"损失什么"列**）｜消费方登记表｜只读直连申报行｜变更通报对象｜运维参数 + 最后核验日期｜迁移窗口承诺（§9 #27）

## §19 组件即库：liubian-kit 基类套件（管理员裁定 2026-10-04 23:05 的落地形态）

**裁定意图翻译**：每个组件写成一个**库**（服务面即库接口）｜每个功能是一个**类**｜需要改写时**继承父类覆写**，不重写。与 §21 洋葱分层合看 = 内层开始沉淀**共享代码资产**，而不只是共享协议。

**落地形态**：家族仓库新增 `liubian-kit/`（版本化内层组件），首批基类全部从**已验证实现**提取，新组件继承即合规：

| 基类 | 提取自 | 免费获得 |
|---|---|---|
| `BaseLiubianService` | infra / 被炉 / 记忆三处 provide 形态 | provide→reflect 回退、`version` 字段、挂载双行日志、`{ok,error}` 绝不抛包装 |
| `BasePullStore` | infra 墓碑流 | `changes({since})` + seq 水位、事件表只增不改、全量快照 |
| `BaseJsonlFile` | 便签 pending_promotions | §7 首行 `_meta`、append-only、读侧容忍缺失、**按键摘除（三元组 session_key+id+queued_at，只删命中行、保留他行）**——青简实证：同 id 重发按双键摘除会误删历史条（v0.7.3 根治） |
| `BaseTombstones` | infra / 被炉双侧 | 墓碑写法、硬拒语义、lift 留痕 |
| （预留）`BaseShadowSession` | 孪生 v2 M1 | `agents.create` 带 agentOptions+setup、照抄+增量、防自环 |

**四条纪律**：
1. **新组件强制走 kit**（继承即合规——"零负担迁移"的本体）；**存量六插件不强制重构**（行为已合规，等价重构各自择窗，不做大爆炸）。
2. kit 是**共享代码依赖 = 洋葱内层组件**：继承者同吃它的 bug——因此 kit 改动 = 可装载变更（**必涨版本**）+ **桩测强制** + §9 #27 迁移窗口适用 + 消费方 pin 版本。
3. kit 归属洋葱内核（建议基建认养，总览出草案）；归属与消费方进家族标准 §10 登记表。
4. 基类只收"形态"、不收"业务"——业务逻辑留在各组件，防止 kit 长成第二个单体。

## §21 洋葱分层调用规则（《合并决断》的制度化）

**层次**（由内向外）：

| 层 | 成员 | 实测特征 |
|---|---|---|
| **内核** | 基建（注册中心/向量控制面/junction 归口）+ `liubian-kit` + 向量服务进程 | 基建零消费家族服务（守夜人申报，最底层实锤） |
| **中层** | 记忆 / 便签 / 被炉 / 孪生 / 博物 | 消费内核服务面与算力端点；中层间互通走服务面 |
| **会话侧** | 各插件养的智能体、被炉房间、留言板 | 走工具面与房间协议，不直接触内核库 |

**规则**：
39. **只许向内调**：外层消费内层的服务面/契约/算力端点；**禁止横向直写**任何组件的库（§6 单写者在此升格为分层规则）。
40. 同层互通一律走**服务面（provide）或已申报的文件接口**，不开第二通道——通道多了就是新的数据孤岛。
41. **失效止于降级链**：任何一层失效，向外的波及必须收敛在"已登记的降级链"内——单组件失效不波及他层功能（《合并决断》的失效隔离目标，也是 10-01 注入器瘫痪连坐事故的反面）。
42. **层的变更须通报**：组件升内层/降外层 = 家族标准 §10 登记表变更，走变更通报对象。
