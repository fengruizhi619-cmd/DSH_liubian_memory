## 0. 一句话

便签系统是流变·记忆的**短期记忆互补件**：以「便签头 + 正文」为单位，把一个对话近期的记忆定量保存（自动多轮聚合 + 主动挂起双来源），每轮按便签头向量余弦最近选 n 篇注入（热记忆），热度以滑动窗口记账（l/m，m=聚合周期），池满赛马淘汰最低分，热度最高者周期性送交流变记忆审核固化为长期记忆。

## 1. 定位与边界

| | 流变·记忆（dsh-liubian） | 流变·便签（本插件） |
|---|---|---|
| 记忆跨度 | 跨对话、跨工作区（长期） | **单对话内**（短期） |
| 组织方式 | 日记流 + tag + 向量联合检索，不限量 | **便签池定量 10 篇**，仅向量检索，赛马生存 |
| 入库节奏 | 每轮一篇日记 | **多轮聚合一篇** + 智能体主动挂起 |
| 数据归属 | liubian.db / 工作区 memory 目录 | `~/.dsh/liubian-notes/`（完全独立） |

- **互补声明**：逐轮入库仍由流变记忆自动承担；便签是**会话级聚合固化**的补充通道。便签的差异价值在：容量受控（赛马逼出"什么值得留下"）、粒度更粗（多轮一篇）、可被智能体**主动**挂起（记忆系统做不到）。
- **不侵入**：不修改 dsh-liubian 任何代码与数据；只用其公开工具面（write / 通路二配置）与向量服务（8082）。

## 2. 便签结构

```
{
  id: "NT-3",
  head: "……",                // 便签头：正文的简介；唯一的向量来源
  body: "……",                // 便签正文：打包的记忆内容
  vector: [……],              // head 的 embedding（落盘缓存，避免重复计算）
  source: "auto | manual",   // 自动聚合 | 主动挂起（两者无任何待遇差别）
  born_turn: 12,
  heat: [30, 35, 41],        // 热度记账：每次被注入记录所在回合号；各条独立存活 R 回合
  diary_ref: null,           // 送审通过后的流变记忆日记号
  submit_attempts: 0,
  status: "active | submitted | rejected | retired"
}
```

- **检索只用向量**：便签不带 tag、不进 tag 索引、不分层；向量服务复用 `dsh-liubian-embed`（localhost:8082，Qwen3-Embedding-0.6B），HTTP 调用、无包依赖；服务不可用 → 便签插件降级为"不注入、只存"，其余功能不受影响。

## 3. 来源一：自动聚合记录

- 每 **R 个人类轮**把这段时间的对话聚合为**一篇**便签（不再每轮聚合）；单篇 ≥1.5KB 可提前封存。
- **R 待实测定值**：管理员定调"看平均每轮对话文本量再决定"。处置：R 做成配置项，P1 先以 **R=5** 起跑，插件同时统计本会话平均每轮文本量；P1 验收时把统计报表交管理员定 R 的正式值。m 恒等于 R（见 §5）。
- 便签头 = 对正文的**一句话简介**，由外部 API 生成（每 R 轮一次小调用）；生成失败回退为"各轮结论首行拼接"。
- 便签正文 = 窗口内每轮的结构化记录（轮号 / 用户问题 / 助手结论 / 关键产物一行），零 LLM 聚合。

## 4. 来源二：智能体主动挂起

- 工具 action `stick(head, body)`：智能体判断"这事后面一定还要用"，主动挂起便签——头自己写（一句话简介），正文自己组织。
- **主动挂起与普通便签没有区别**（管理员拍板）：同池、同向量检索、同热度记账、同赛马、同送审，无初始热度加成。

## 5. 注入与热度（热 / 冷记忆）

**注入**：
- 查询向量来源 = **该轮对话 + 上一轮完整问答**（管理员拍板）。具体构成：本轮用户消息 + 上一轮用户消息与助手回复全文，拼为查询文本后取 embedding。
- 与池内所有便签头向量算余弦相似度，取**最近的 n=3 篇**注入 `<liubian-notes>` 块。被注入的 = 热记忆，其余 = 冷记忆。
- 单轮注入预算 ≤2KB；命中篇目正文超长时截断（全文用 `show` 工具取）。

**热度记账（m = R，管理员拍板：与聚合周期一致，新旧交替刚好配对）**：
- 便签每被注入一次 → 追加一条热度记录（记录当时回合号）。
- 每条热度记录**独立维持 m=R 个回合**，到期即从记账中消失（滑动窗口，互不影响）。
- **热度分 = l / m**：l = 当前仍未过期的热度记录条数，m = 单条维持回合数（=R）。同一条便签同一回合至多记一条，故热度分 ∈ [0,1]，是归一化的近期热度。
- **配对语义**：聚合节拍与热度寿命同为 R——一篇便签从诞生起，恰有一个完整周期的时间靠注入攒热；下一批新便签入池时，上一批的旧热度恰好清零，赛马只看"本周期的表现"。

## 6. 赛马淘汰与判重

- **赛马**：池满（**N=10，定案**；后期依实践再议扩缩）且新便签需入池时 → 踢掉**热度分最低**的一篇（并列最低踢 `born_turn` 最旧者），由最新录入的便签顶替。被踢者写入回收站（`retired.jsonl`，不再注入、可查可救）。
- **判重（不允许重复）**：新便签入池前，其便签头向量与池内所有便签头向量算余弦，**相似度 >0.90 视为重复 → 拒收入池**（管理员拍板；正文完全相同必判重）。阈值待后续实践测试再精调；回收站同样参与判重，防淘汰-重录死循环。
- 已提交（`submitted`）的便签受保护，不参与赛马淘汰。

## 7. 送审（便签 → 流变记忆固化）

- **节拍**：每 K=20 个人类轮审一次，每次至多 1 篇。
- **候选（管理员拍板：照 v2）**：**热度分最高**且未提交过的便签；池内热度分全为 0 时，回退取存在周期最长者。
- **审核**：复用通路二——API-A 把便签起草成归档日记，API-B 五维审「是否值得长期保存」。
  - 通过 → 调流变记忆 `write`（`kind=log`，tags：`便签归档` + `会话归档` + 工作区标签）得 `Dxxxx` → 便签 `status=submitted`、`diary_ref` 落号，**继续留池但不再占赛马名额**（受保护）。
  - 拒绝 → `submit_attempts+1`；累计 2 次冻结（防烧钱），可手动强提。
  - 通路二不可用 → 跳过本次，不直通落库。

## 8. 金字塔——暂不实现

管理员拍板（2026-10-01）：**先不管**。便签不分层、无降层机制；`layer` 字段从数据模型移除。如后期实践需要，再从"统计标签"形态起步（v2 读法 A）。

## 9. 工程形态

- **独立插件** `dsh-liubian-notes`：独立爆炸半径 + 独立总开关 `liubianNotes.enabled`；`main.mjs`/`impl.mjs` 两层（缓存戳动态导入）、注入消息四要件、钩子整段 try/catch、`__test` 桩测缝、超 20KB 临时文件通道。
- **工具面** `_dsh_external_dsh_liubian_note`：`list`（看池+热度分）/ `show`（读全文）/ `stick`（主动挂起）/ `promote`（手动强提）/ `drop` / `restore`（回收站）。
- 存储：`~/.dsh/liubian-notes/<工作区编码>/<会话8位>.json`（含向量缓存）+ `retired.jsonl`；不碰 `~/.dsh/liubian/`、不碰 liubian.db。会话死后便签保留 30 天（可配）供补送审，到期入回收站。
- 配置项：`poolSize=10`、`injectTop=3`、`aggregateRounds=R`（默认 5，待实测）、`dedupThreshold=0.90`、`reviewEveryK=20`、`retireAfterDays=30`、`enabled`。
- 代码落位：`E:\DSH_data\流变系统\dsh-liubian-notes\`。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 向量服务（8082）挂了便签全盲 | 降级为只存不注；恢复后补算缺失向量；不影响记忆/被炉/孪生 |
| 便签头质量差 → 向量检索失准 | 头由外部 API 生成（专职简介）；`list` 显示头供人工纠偏；`stick` 时智能体自查头质量 |
| m=R 配对导致冷启动期（首周期内池中便签全靠当期热度） | 属预期行为：首周期无历史热度可比，赛马并列时按 born 最旧淘汰兜底 |
| 赛马踢掉刚入池的高潜便签 | 新便签首注入机会由余弦相关性保证（贴题者自然高热）；回收站可 restore |
| 与记忆注入块叠加撑大上下文 | 便签预算 ≤2KB/轮；总开关一键关 |
| 会话号键控歧义（fork/恢复） | 键 = 会话 SHA256 前 8 位；fork 天然独立成池 |

## 12. 验收口径

**P1**：
1. 连续对话 ≥12 轮，自动聚合产出 ≥2 篇便签，`<liubian-notes>` 每轮 ≤2KB 且命中篇目随话题变化（"该轮+上一轮"查询向量生效）。
2. `stick` 挂起一篇 → 下一轮按向量命中注入；构造相似头再挂 → 相似度 >0.90 被判重拒收。
3. 池满构造赛马：最低分者入回收站、新便签顶替；`restore` 可救回。
4. 手动 `promote` → 流变记忆出现 `kind=log` 日志（标签含 便签归档），便签 `diary_ref` 落号。
5. 停掉 8082 → 降级不注入、无报错拖垮本轮；拉起后自愈。
6. 输出本会话**平均每轮文本量统计**，供管理员定 R 正式值。

**P2**：K 节拍自动送审走通（含拒绝冻结、通路二不可用跳过）；m=R 热度衰减与赛马在长对话中实测一轮完整新旧交替。
