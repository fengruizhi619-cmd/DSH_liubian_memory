# 流变·记忆（DSH 版）

> 本技能是 Codex 侧 `memory-skill` 的 DSH 移植版。后端与数据完全复用：
> 日记、标签、用户都在 `E:\DSH_data\.memory_registry\liubian.db`，
> **两端同源** —— DSH 写的日记，Codex 侧 `#m` 流程能立刻检索到，反之亦然。
> 差别只在于调用方式：Codex 侧走 `python memory.py ...` 命令行，DSH 侧走原生工具。

## 自动日记（外部 API 撰写，下一轮写上一轮）
**先看接入卡上的 `[自动日记]` 那一行**，它决定你这轮要不要自己写日记：

| 接入卡显示 | 你要做什么 |
|---|---|
| `[自动日记] 已开启` | **不要 `write`** —— 插件会在下一轮开始时把上一轮的**完整对话**送给外部 API 撰写。手动写会写重。 |
| `[自动日记] 未开启` | 仍按下面「1. 写日记」手动写。 |

机制（供理解，不需要你操作）：

- **采集**：订阅 `session/event` 累积每轮的「提问 + 助手正文 + 工具轨迹」，**免疫上下文压缩**
- **写入时机**：下一轮的第一步（`agent/pre-step`）→ 所以叫"写上一轮"
- **末轮不兜底**：会话结束/落盘时插件不做任何事；没写的轮次等**下一次对话**开轮时补。所以某轮之后再也不回来，那轮就不会有日记（这是明确设定，不是 bug）
- **选标签（两步）**：
  1. 把上一轮的**助手正文**送本地向量模型（llama.cpp `qwen3-emb`，端口 8082，1024 维）得到查询向量；
  2. 与**本地 13930 个标签各自的向量**算余弦相似度，取**前 100 个**作为候选送进外部 API。
  标签向量只在首次（或标签表变化后）建一次并落盘缓存（`~/.dsh/liubian/tag_vectors.bin`，约 57MB），
  建缓存期间那一轮自动退回"整张标签表"。向量服务没起 / 缓存没建好 → 一律退回整张表，
  语义选标签只是**优化**，不是依赖。
- **输入**：上一轮完整对话 + 上述 100 个候选标签（按余弦降序）+ 工作区署名
- **约束**：标签 ≥5 且**优先逐字复用**候选标签（不要改写成近义词），也允许新建；每篇正文 **≤500 字，超了自动拆成多篇，篇数不设上限**
- **写库前的底线**：模型给的标签不足 5 个（后端会拒）→ **重试一次**；仍不足就**不写库**、落待补队列。
  **绝不拿标签表里最常用的标签去凑数**（那等于往检索索引里灌假标签）
- **失败**：不阻塞对话 → 落 `~/.dsh/liubian/pending_diaries.jsonl`（只存轮次原文，不存整份输入），
  之后每轮自动补写（单条最多重试 5 次）
- 运维工具：`_dsh_external_dsh_liubian_diary`
  （`status` 看状态含**标签选择模式与向量缓存是否就绪**｜`preview` **预览将发给 API 的完整输入 + 相似度前 12 的候选标签**（不调用 API）｜`run` 立刻补写｜`retry` 重试待补｜`enable` / `disable`）

## 联合检索注入（每轮自动，tag 一路 + 语义一路）

**每轮开新输入时**，插件会做一次双路检索并把**前 10 篇的正文全文**塞进上下文
（`<liubian-memory hits="10" score="cos+tag">`）：

1. **查询文本** = 上一轮助手回答 + 本轮用户问题（两者都截断到预算内）
2. **语义一路**：把查询文本送本地向量模型（llama.cpp `qwen3-emb`，8082，1024 维），
   与库里 6114 篇日记的向量算余弦。
3. **tag 一路**：把**同一段查询文本 + 标签候选表**送外部 API，让模型挑 **5 个**标签；
   候选表取法与写日记同款（语义选前 100 个，复用同一份标签向量缓存）。
   挑完后做字面检索（标签用 `docs['index:*']` 的 tag 索引）。
4. **融合**：`综合分 = 语义余弦 + 0.5 × (命中标签数 / 5)`，降序取前 10 篇，注入全文。

**为什么是"余弦 + 标签加成"而不是线性加权**（这是实测调出来的，别再改回去）：
线性加权（`w·命中率 + (1-w)·cos`）下，"命中 1/5"等于 cos 意义上的 0.2 —— 比两个平庸
语义分之间的差距还大，于是只蹭到一个跨领域同名标签（如"双通道检索""联合"）的无关日记
会被顶进前三（实测 `D0598` 语义仅 0.31 却排第二）。IDF 加权、IDF 求和、平方、1.5 次方
四种补丁都试过：前两种没治住，后两种把 tag 一路彻底压死。最终改成**语义分是底分、
标签命中是封顶 0.5 的加成**，两边的作用都保住了。

运维开关（`~/.dsh/liubian/config.json`，改完下一轮生效）：
`memoryInject`（总开关，关掉退回旧的"检索摘要"召回）｜`memoryTopN`（注入几篇，默认 10）｜
`memoryWTags`（标签加成上限，默认 0.5）｜`memoryScope`（`global` 默认跨 14 个工作区；`workspace` 只查当前工作区）｜
`memoryContentChars` / `memoryTotalChars`（单篇与整块的字符预算）。

## 语义向量检索（显式 search 时自动叠加）
检索时自动叠加语义向量，无需额外参数：
- 向量模型：本地 llama.cpp 嵌入服务 `http://127.0.0.1:8082/v1/embeddings`（Qwen3-Embedding-0.6B，1024 维）
- 索引存 SQLite `embeddings` 表，搜索时自动增量索引缺失向量
- **融合排序：tag 命中与语义余弦 1:1**（各乘 0.5）；tag 未命中但语义相关的会以「(语义命中)」补召回
- 输出会写明 `语义检索: 已启用(向量 n 篇, 融合 tag+语义)` 或 `语义检索: 不可用(回退纯tag)`
- **服务不可用时静默回退纯 tag，不影响流程**。向量服务由**独立插件 `dsh-liubian-embed`** 负责，
  它在插件加载时会探活并（离线时）后台带起服务，所以**通常不需要手动拉起**；
  想立刻拉起并等待就绪才用 `_dsh_external_dsh_liubian_embed action=ensure`
  （同一个工具还能 `status` 看状态、`stop` 关停释放显存、`restart` 重启）

**技能总揽也一起检索**：搜索时自动把每个技能的 `SKILL.md` 做语义检索，命中后单独列「技能检索」，
用于写作时找文风包（如败犬 → `makeine-losing-heroine`）、课程知识（如机器视觉 → `machine-vision-course`）。
只索引 `SKILL.md`，技能内部细读/蒸馏文档不索引，避免低信息量文档稀释检索。
